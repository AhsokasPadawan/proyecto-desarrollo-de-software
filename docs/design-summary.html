Flujo 1: Validación de Jugada, Simulación Reversible de Jaque y Transición de Estado

Muestra cómo interactúan ChessGame, IGameState, IMovementRule, MoveCommand, CheckDetector e IGameObserver al invocar makeMove(from, to).

Paso 1 • Estado y Turno
¿Fase acepta jugadas y origen es del turno activo?
Consulta currentState.canAcceptMoves() y board.getPieceAt(from).
✗ Falla → GAME_OVER / EMPTY_ORIGIN / WRONG_TURN
Paso 2 • Geometría
¿Destino está en Pseudo-Legal Moves?
piece.getPseudoLegalMoves(from, boardQuery) evalúa rayos/saltos y obstáculos.
✗ Falla → ILLEGAL_MOVE
Paso 3 • Simulación
¿Deja al propio Rey en Jaque?
Ejecuta cmd.execute() → consulta CheckDetector.isKingInCheck. Si hay jaque propio, llama a cmd.undo().
✗ Falla → KING_LEFT_IN_CHECK
Paso 4 • Command
Confirmar en CommandHistory
Se apila el MoveCommand en undoStack, se limpia redoStack y se alterna currentTurn.
✓ Reversible con undo()
Paso 5 • Patrón State
Transición Polimórfica de Fase
Evalúa (isInCheck, hasAnyLegalMove) vía Lookup Table → IN_PROGRESS, CHECK, CHECKMATE o STALEMATE/DRAW.
✓ Cero bloques switch
Paso 6 • Observer
Emisión de GameSnapshot y MoveResult
Notifica a cada IGameObserver con el nuevo GameSnapshot inmutable y retorna { success: true }.
✓ UI React re-renderiza

Flujo 2: Matriz de Transición del Patrón State (Lookup Table)

Al cambiar el turno, el siguiente IGameState se selecciona sin switch evaluando dos predicados sobre el jugador entrante:

¿Rey en Jaque? ¿Tiene Legal Moves? ¿Regla 50m / 3x / Insuf.? Clase IGameState Resultante
false true false NormalPlayState (IN_PROGRESS)
true true false CheckState (CHECK)
true false — CheckmateState (CHECKMATE)
false false — StalemateState (STALEMATE)
— true true DrawState (DRAW)

Flujo 3: Adaptador React + Tailwind en 2 Clics (Cero useEffect)

Cómo fluye la interacción del usuario respetando las reglas de codificación de React:

  1. 1. Suscripción Declarativa: El componente invoca useSyncExternalStore(game.subscribe, game.getSnapshot). Cuando el Core cambia, React recibe el nuevo GameSnapshot inmutable.
  2. 2. Primer Clic (Selección): En onSquareClick(pos), si hay una pieza del turno activo, guarda selectedPos y llama a game.getLegalMoves(pos) para resaltar destinos válidos.
  3. 3. Segundo Clic (Acción directa en handler): Llama a const res = game.makeMove(selectedPos, targetPos). Si falla, busca el mensaje en REJECTION_MESSAGES[res.reason]; si tiene éxito y el modo IA está activo, dispara aiStrategy.chooseMove(game) en el mismo flujo de evento.
